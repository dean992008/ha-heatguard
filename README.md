# HeatGuard для Home Assistant

Локальная custom integration для **HeatGuard WEB Server V2.10**. Проверена на устройстве, названном владельцем Mitsubishi Heavy HeatGuard 140SX; интеграция не определяет модель автоматически. Облако не требуется.

## Установка

1. Скачайте исходники из [GitHub](https://github.com/dean992008/ha-heatguard).
2. Скопируйте `custom_components/heatguard` в `/config/custom_components/heatguard` на сервере Home Assistant.
3. Перезапустите Home Assistant.
4. Настройки → Устройства и службы → Добавить интеграцию → HeatGuard.
5. Укажите адрес своего контроллера, например `http://192.0.2.10` (это пример, замените своим адресом), имя пользователя и пароль. Пустой пароль поддерживается.

Для смены адреса или учётных данных используйте «Перенастроить». При ошибке авторизации доступна повторная аутентификация. Пустое поле пароля означает пустой пароль, включая перенастройку. Учётные данные хранятся в конфигурации HA; не добавляйте её в публичный репозиторий.

## Возможности

Интеграция создаёт **22 сущности**:

| Сущности | Назначение |
| --- | --- |
| 16 sensor | Все показатели JSON контроллера |
| 1 binary_sensor | Активность компрессора: CmpFreq > 0 |
| 1 switch | Разрешение работы: Mode_s |
| 2 select | Режим Cooling / Heating / Remote и включение Day / Night / Schedule |
| 2 text | Уставки нагрева и охлаждения в °C |

Разрешение работы и фактическая активность разделены. Контроллер может разрешать работу, но останавливать компрессор по расписанию. Переключатель `Operation permitted` отражает разрешение, а `Compressor active` — наблюдаемую частоту компрессора. Последний не подтверждает работу циркуляционного насоса.

| Поле | Показатель | Родная единица |
| --- | --- | --- |
| Mode | Сообщаемый режим | текст |
| Warning | Сообщение состояния | текст |
| Setpt | Активная уставка | °C |
| COP | COP | безразмерный |
| InWater | Входящая вода | °C |
| OutTemp | Наружная температура | °C |
| OutWater | Выходящая вода | °C |
| OutHTemp | Датчик OutHTemp, назначение не установлено | °C |
| LiqRef | Жидкий хладагент | °C |
| DisTemp | Температура нагнетания | °C |
| GasRef | Газообразный хладагент | °C |
| CmpFreq | Частота компрессора | Hz |
| Flow | Расход воды | m³/h |
| Curent | Ток | A |
| HLoad | Тепловая нагрузка | W |
| ElPower | Электрическая мощность | W |

Мощности HLoad и ElPower пересчитываются из кВт контроллера в W: 1 кВт = 1000 W. При обновлении существующей установки HA может сохранить прежнюю единицу отображения; выберите W в настройках этих двух sensor-сущностей. Все числовые показатели мгновенные, не счётчики энергии. HA может преобразовать температурные sensor-сущности в единицы общих настроек. Текстовые поля уставок явно обозначены °C и не преобразуются.

Уставки редактируются через text-сущности: введите `34.0` или `8,0`, без единиц, не более одного знака после разделителя. Допустимые температурные диапазоны **неизвестны**. Number-сущности потребовали бы объявить неподтверждённые min/max. Валидация проверяет формат числа, а не пригодность температуры для оборудования.

## Обмен и управление

Опрос каждые **15 секунд**: последовательные GET `/CurentParam_s.cgx` и `/setpoint_s.cgi`. Таймаут запроса — 10 секунд. При потере связи, неполных данных или ошибке авторизации сущности становятся unavailable; успешный опрос восстанавливает доступность.

Команда под общей блокировкой перечитывает форму, меняет одно поле, передаёт все пять настроек и значение кнопки `set`, затем перечитывает форму и сверяет все пять полей. Опрос использует ту же блокировку. Неизменённые уставки передаются в исходном виде, изменённая — числом без °C, как после обработки JavaScript контроллера. HTTP 200 без совпадения настроек не считается подтверждением применения.

Автоматических повторов записи нет. При таймауте POST результат может быть неопределённым: дождитесь свежих состояний перед повторением. Конкурентные команды этой интеграции выполняются последовательно. Другой клиент или браузер может изменить форму между GET и POST; известного механизма условной записи у сервера нет. Проверка результата обнаруживает расхождение после команды, но не обеспечивает распределённую блокировку.

Используется HTTP Basic по протоколу указанного адреса; перенаправления отключены. Интеграция предназначена для локальной сети. Warning читается как текст состояния, без классификации тревог. Тревоги, счётчики, сетевые настройки и прошивка вне объёма проекта.

**Автоматизации питания не входят в интеграцию.** Состояние `Operation permitted` можно использовать в собственной автоматизации: запоминать разрешение до автоматической остановки и восстанавливать только ранее включённое разрешение, сохраняя ручную остановку. Интеграция не зависит от внешнего датчика сети и сама не меняет разрешение при потере связи или перезапуске HA.

## Проверка и ограничения

Реальные GET и периодическое обновление данных проверены с WEB Server V2.10. Интеграция установлена и загружена на Home Assistant 2026.8.0 / Python 3.14; все 22 сущности были доступны. На контроллере исследованы форма и inp_int.js: скрипт очищает единицы, поддерживает минус и разделитель, ограничивает дробь одним знаком и не задаёт min/max.

**POST проверен только на mock-сервере и заглушках.** Команды изменения состояния реальному насосу не отправлялись. Фактическое применение контроллером, безопасные диапазоны уставок и другие версии прошивки не проверены.

Публичные fixtures синтетические: сохраняют исследованный формат формы, украинские значения и единицы, но не содержат адресов, идентификаторов установки или реальных показателей владельца. Исходные ответы контроллера, служебные скрипты установки и локальные отчёты не публикуются.

```sh
python -m venv .venv
# Активируйте окружение подходящим для вашей ОС способом, затем:
pip install -r requirements-test.txt
python -m pytest -q
```

36 тестов проверяют протокол, HTTP mock с UTF-8 и Basic Auth с пустым паролем, все поля записи, сохранение настроек, конкурентные команды, таймауты и ошибки, сверку результата, сущности и их unavailable, config flow и setup/unload. Без установленного HA проверки его классов пропускаются; протокольные тесты остаются доступными. В CI устанавливается HA и пропуск его проверок запрещён.

Архитектура использует [DataUpdateCoordinator](https://developers.home-assistant.io/docs/integration_fetching_data/) и [config flow](https://developers.home-assistant.io/docs/core/integration/config_flow/). Ошибки можно сообщать в [Issues](https://github.com/dean992008/ha-heatguard/issues).
